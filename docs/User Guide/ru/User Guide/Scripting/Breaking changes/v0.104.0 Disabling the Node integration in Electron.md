# v0.104.0: Отключение интеграции Node в Electron
## Введение

До v0.104.0 код, выполняемый на уровне рендерера (например, клиентские скрипты), мог напрямую подключать `@electron/remote` или даже API Node.js (например, `process` или `fs`). Хотя это давало широкие возможности, такой подход создавал значительную поверхность атаки — любая XSS-уязвимость или недоверенный скрипт в заметке превращались в удалённое выполнение кода на хосте.

Чтобы снизить этот риск, клиентская часть больше не имеет доступа к этим API, и всё взаимодействие должно проходить через <a class="reference-link" href="../Script%20API/Electron%20API.md">Electron API</a>.

> [!NOTE]
> Если это изменение API вызывает проблемы в некоторых ваших клиентских скриптах, рассмотрите следующие варианты:
> 
> *   Взаимодействие с <a class="reference-link" href="../Backend%20scripts.md">серверными скриптами</a>, у которых больше свободы действий.
> *   [Сообщить об этом](../../Troubleshooting/Reporting%20issues.md) как о запросе новой функции.

## Обзор API

Клиентский и серверный API находятся в глобальной переменной `api`, которую можно использовать в любом месте скрипта. Например, чтобы показать сообщение пользователю, можно использовать следующий клиентский скрипт:

```javascript
api.showMessage("Hello world.");
```

Electron API устроен иначе: он находится в `window.electronApi` (предоставляется preload-скриптом десктопного приложения), а не в `api`, и доступен только в десктопной сборке Electron. Клиентские скрипты, которые его используют, должны проверять его наличие с помощью `if (window.electronApi)`, чтобы корректно работать в браузерной и автономной (WASM) сборках.

```javascript
window.electronApi?.window.setZoomFactor(1.2);
```

## Дополнительная защита

В некоторые API встроены дополнительные механизмы защиты, предотвращающие несанкционированный доступ.

Группа `shell` проходит самую строгую проверку: `openExternal` ограничена разрешённым списком URL-схем (блокируются `file:`, `smb:`, схемы класса Follina и т. д.), `openPath` должен указывать путь внутри каталога данных Trilium или временного каталога, а `downloadURL` привязан к собственному источнику (origin) приложения. Некорректные входные данные вызывают исключение на стороне основного процесса, а не передаются дальше без проверки.
