# Использование Docker
Официальные образы Docker публикуются на Docker Hub для архитектур **AMD64**, **ARMv7** и **ARM64/v8**: [https://hub.docker.com/r/triliumnext/trilium/](https://hub.docker.com/r/triliumnext/trilium/)

## Предварительные требования

Убедитесь, что в вашей системе установлен Docker.

Если вам нужна помощь с установкой Docker, обратитесь к [документации по установке Docker](https://docs.docker.com/engine/install/).

По умолчанию контейнер запускается от имени root, подготавливает каталог данных и затем запускает Trilium от имени непривилегированного пользователя. Его также можно запускать полностью без прав root — см. раздел _Запуск от имени непривилегированного пользователя (non-root)_ ниже.

> [!WARNING]
> Если вы используете сетевую папку SMB/CIFS в качестве каталога данных Trilium, [необходимо](https://github.com/TriliumNext/Notes/issues/415#issuecomment-2344824400) добавить параметры монтирования `nobrl` и `noperm` при монтировании ресурса SMB.

## Запуск с помощью Docker Compose

### Скачайте актуальный docker-compose.yml:

```
wget https://raw.githubusercontent.com/TriliumNext/Trilium/master/docker-compose.yml
```

При желании отредактируйте файл `docker-compose.yml`, чтобы настроить параметры контейнера перед запуском. Если не указано иное, каталогом данных будет `trilium-data` рядом с `docker-compose.yml`, а контейнер будет доступен на порту 8080.

Чтобы хранить данные в другом месте, измените запись `volumes` в `docker-compose.yml`, указав другой путь на хосте до двоеточия (например, `- /srv/trilium-data:/home/node/trilium-data`). Путь после двоеточия оставьте без изменений.

### Запустите контейнер:

Выполните следующую команду для запуска контейнера в фоновом режиме:

```
docker compose up -d
```

## Запуск без Docker Compose / Дополнительная настройка

### Загрузка образа Docker

Чтобы загрузить образ, выполните следующую команду, заменив `[VERSION]` на нужную версию или тег, например `v0.91.6` или `latest` (список опубликованных тегов см. на [https://hub.docker.com/r/triliumnext/trilium/tags](https://hub.docker.com/r/triliumnext/trilium/tags)):

```
docker pull triliumnext/trilium:v0.91.6
```

**Предупреждение:** старайтесь не использовать тег «latest», так как это может привести к автоматическому обновлению вашего экземпляра до новой минорной версии, что способно нарушить синхронизацию или вызвать другие проблемы.

### Подготовка каталога данных

Для хранения данных Trilium требуется каталог на хост-системе. Этот каталог должен быть примонтирован в контейнер Docker с правами на запись.

### Запуск контейнера Docker

=== "Только локальный доступ"

    Запустите контейнер так, чтобы он был доступен только с localhost. Такой вариант подходит для тестирования или при использовании прокси-сервера, например Nginx или Apache.

    ```sh
    sudo docker run -t -i -p 127.0.0.1:8080:8080 \
    	-v ~/trilium-data:/home/node/trilium-data \
    	triliumnext/trilium:[VERSION]
    ```

    1.  Убедитесь, что контейнер запущен, с помощью `docker ps`.
    2.  Откройте Trilium в браузере по адресу `127.0.0.1:8080`.

=== "Доступ в локальной сети"

    Чтобы сделать контейнер доступным только в вашей локальной сети, сначала создайте новую сеть Docker:

    ```sh
    docker network create -d macvlan -o parent=eth0 --subnet 192.168.2.0/24 --gateway 192.168.2.254 --ip-range 192.168.2.252/27 mynet
    ```

    Затем запустите контейнер с этими сетевыми настройками:

    ```sh
    docker run --net=mynet -d -p 127.0.0.1:8080:8080 -v ~/trilium-data:/home/node/trilium-data triliumnext/trilium:-latest
    ```

    Чтобы задать другой идентификатор пользователя (UID) и группы (GID) для сохраняемых данных, используйте переменные окружения `USER_UID` и `USER_GID`:

    ```sh
    docker run --net=mynet -d -p 127.0.0.1:8080:8080 -e "USER_UID=1001" -e "USER_GID=1001" -v ~/trilium-data:/home/node/trilium-data triliumnext/trilium:-latest
    ```

    Узнайте локальный IP-адрес с помощью `docker inspect [container_name]` и подключайтесь к сервису с устройств в локальной сети.

    ```sh
    docker ps
    docker inspect [container_name]
    ```

=== "Глобальный доступ"

    Чтобы разрешить доступ с любого IP-адреса, запустите контейнер следующим образом:

    ```sh
    docker run -d -p 0.0.0.0:8080:8080 \
    	-v ~/trilium-data:/home/node/trilium-data \
    	triliumnext/trilium:[VERSION]
    ```

    Остановить контейнер можно командой `docker stop <CONTAINER ID>`, где идентификатор контейнера можно узнать через `docker ps`.

### Пользовательский каталог данных

Для использования собственного каталога данных укажите:

```
-v ~/YourOwnDirectory:/home/node/trilium-data triliumnext/trilium:[VERSION]
```

Если вы хотите запустить экземпляр с нестандартным расположением данных, используйте флаг тома следующим образом: `-v ~/YourOwnDirectory:/home/node/trilium-data triliumnext/trilium:<VERSION>`. Важно понимать, как в Docker работают тома: первый путь — это ваш каталог на хосте, а второй — путь внутри контейнера, к которому он привязывается. [https://docs.docker.com/storage/volumes/](https://docs.docker.com/storage/volumes/) Путь до двоеточия обозначает каталог на хосте, а путь после двоеточия — каталог внутри контейнера. Подробнее см. в [документации Docker Volumes](https://docs.docker.com/storage/volumes/).

### Примечание о часовых поясах

По умолчанию контейнер работает в часовом поясе UTC. Предоставленный файл `docker-compose.yml` монтирует `/etc/localtime` хоста, чтобы контейнер использовал часовой пояс хоста. Если на хосте нет `/etc/localtime` или вы не используете docker-compose, задайте переменную окружения `TZ` с [идентификатором TZ](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones) вашего местного часового пояса (например, `TZ=America/New_York`).

## Запуск от имени непривилегированного пользователя (non-root)

По умолчанию контейнер запускается от имени root, передаёт каталог данных пользователю `node` (UID и GID `1000`, либо значения `USER_UID` и `USER_GID`) и затем запускает Trilium от его имени. Некоторые среды вообще не позволяют контейнеру запускаться от имени root — например, rootless Docker или Podman, а также Kubernetes с параметром `runAsNonRoot`. Начиная с версии v0.107.0, тот же образ можно запускать полностью от имени непривилегированного пользователя.

Чтобы запустить Trilium от имени непривилегированного пользователя, укажите пользователя с помощью флага Docker `--user`:

```sh
docker run -d -p 8080:8080 --user 1000:1000 -v /srv/trilium-data:/home/node/trilium-data triliumnext/trilium:[VERSION]
```

В Docker Compose добавьте `user:` в описание службы в `docker-compose.yml`:

```yaml
services:
  trilium:
    user: "1000:1000"
```

Образ также поддерживает запуск с корневой файловой системой только для чтения и без каких-либо capabilities, например с флагами `--read-only --tmpfs /tmp --cap-drop ALL --security-opt no-new-privileges`.

Без прав root контейнер не может изменять владельца файлов, поэтому:

*   Каталог данных на хосте должен уже существовать и принадлежать этому пользователю до запуска контейнера. Если каталог отсутствует, Docker создаст его от имени root, и Trilium не сможет в него писать. Например:
    
    ```sh
    mkdir -p /srv/trilium-data
    sudo chown 1000:1000 /srv/trilium-data
    ```
*   Именованный том вместо каталога на хосте работает только для UID `1000`: Docker назначает новому тому владельца каталога данных в образе, которым является пользователь `node`.
*   Переменные `USER_UID` и `USER_GID` игнорируются. Пользователь определяется исключительно параметром `--user` или `user:`.

Если Trilium не может использовать свой каталог данных, он завершает работу при запуске и выводит, какой каталог или какие файлы недоступны, кому они принадлежат, а также команду для исправления ситуации.

> [!NOTE]
> Установка, которая ранее запускалась от root, оставляет файлы с владельцем UID `1000` (или `USER_UID`, если эта переменная была задана). Чтобы перевести её на `--user`, либо используйте тот же UID, либо предварительно передайте права на каталог данных новому пользователю, например командой `sudo chown -R 1001:1001 /srv/trilium-data`.
