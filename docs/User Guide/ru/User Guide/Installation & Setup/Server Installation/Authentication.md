# Аутентификация
## Отключение аутентификации

Если вы запускаете Trilium только на `localhost` или аутентификация выполняется другим компонентом, вы можете отключить аутентификацию Trilium, добавив следующие строки в `config.ini`:

```
[General]
noAuthentication=true
```

Начиная с версии v0.94.1, отключение аутентификации также отключает <a class="reference-link" href="Multi-factor%20authentication%20with%20TOTP.md">многофакторную аутентификацию</a>.

## Защита от подбора пароля (brute-force)

Trilium ограничивает каждый IP-адрес 10 неудачными попытками входа за 15 минут. Как только адрес достигает этого лимита, Trilium отклоняет все дальнейшие попытки с него, включая правильные, пока не пройдут 15 минут. Страница входа при этом показывает _Too many login attempts_; остальные клиенты получают HTTP-статус 429.

Ограничение применяется ко всем способам входа с паролем:

*   Страница входа.
*   Настройка <a class="reference-link" href="../Synchronization.md">синхронизации</a> из настольного или мобильного приложения.
*   Подключение <a class="reference-link" href="../Web%20Clipper.md">Web Clipper</a> или приложения Android sender.
*   Запрос токена через <a class="reference-link" href="../../Advanced%20Usage/ETAPI%20(REST%20API).md">ETAPI (REST API)</a>.

Все они учитываются в общем лимите, причём неверный пароль, неверный одноразовый пароль и неверный код восстановления считаются за одну неудачную попытку каждый. Успешные входы не учитываются.

Ограничение действует на IP-адрес, а не на учётную запись, поэтому злоумышленник не сможет заблокировать вас, совершая неудачные попытки входа со своего адреса. Счётчик хранится в памяти: перезапуск сервера сбрасывает его.

> [!IMPORTANT]
> За обратным прокси Trilium видит все запросы как поступающие от прокси, если он не настроен как <a class="reference-link" href="2.%20Reverse%20proxy/Trusted%20proxy.md">доверенный прокси</a>. В этом случае все клиенты делят один общий лимит, и несколько неверных попыток от кого угодно заблокируют всех пользователей.

### Блокировка повторных неудачных попыток с помощью fail2ban

На неудачную попытку на странице входа сервер отвечает HTTP-статусом 401 и записывает в <a class="reference-link" href="../../Troubleshooting/Error%20logs/Backend%20(server)%20logs.md">журналы бэкенда (сервера)</a> следующую строку:

```
WARNING: Wrong password from 203.0.113.7, rejecting.
```

Когда включена <a class="reference-link" href="Multi-factor%20authentication%20with%20TOTP.md">многофакторная аутентификация</a>, неверный одноразовый пароль или код восстановления записывается в журнал как `Wrong totp`. Такие инструменты, как fail2ban, могут отслеживать эту строку журнала или ответы 401 на `POST /login` в журнале доступа обратного прокси, чтобы блокировать адрес более чем на 15 минут.

## Как работают сессии

После входа в Trilium приложение сохраняет информацию о входе в cookie в браузере, а также в виде сессии на сервере.

Если установлен флажок «Запомнить меня» (Remember me), срок действия входа истекает через 21 день. Этот период можно изменить, задав значение `Session.cookieMaxAge` в `config.ini`. Например, чтобы сессия истекала через один день:

```
[Session]
cookieMaxAge=86400
```

Если флажок «Запомнить меня» снят, поведение отличается. На уровне клиента/браузера аутентификация не имеет срока действия, но автоматически очищается сразу после закрытия браузера. Тем не менее сервер также аннулирует эту аутентификацию примерно через 24 часа после _последнего взаимодействия с приложением_.

Изменение или сброс пароля завершает все сессии, включая ту, в которой было выполнено изменение: открытые вкладки возвращаются на экран входа, где нужно снова войти с новым паролем. Это также касается случаев, когда пароль изменён на другом экземпляре и дошёл до сервера через синхронизацию.

Изменение пароля не отзывает токены <a class="reference-link" href="../../Advanced%20Usage/ETAPI%20(REST%20API).md">ETAPI (REST API)</a>. Это отдельные учётные данные для скриптов и интеграций, и они продолжают работать до тех пор, пока вы их не удалите. Если вы подозреваете, что кто-то получил ваш cookie сессии, смените пароль, затем перейдите в <a class="reference-link" href="../../Basic%20Concepts%20and%20Features/UI%20Elements/Options.md">Настройки</a> → _ETAPI_ и удалите все незнакомые токены (ориентируясь на их названия и дату _Created_), так как любой, у кого есть ваша сессия, может создавать новые токены.

## Просмотр активных сессий

Сессии входа теперь хранятся в той же <a class="reference-link" href="../../Advanced%20Usage/Database.md">базе данных</a>, что и пользовательские данные. Чтобы просмотреть активные сессии, откройте <a class="reference-link" href="../../Advanced%20Usage/Database/Manually%20altering%20the%20database/SQL%20Console.md">SQL-консоль</a> и выполните следующий запрос:

```
SELECT * FROM sessions
```

Истёкшие сессии периодически очищаются сервером, обычно раз в час.
