# ID заметки
В то время как некоторые приложения используют имена файлов для уникальной идентификации заметок, Trilium использует концепцию ID заметки.

В общем случае ID заметки — это 12-символьная буквенно-цифровая последовательность (включая строчные и прописные буквы), случайно генерируемая для каждой новой заметки.

## Как импорт/экспорт влияет на ID заметок

При экспорте заметок их ID заметки сохраняется в метаданных экспорта. Однако при обратном импорте для всех заметок генерируется новый ID заметки. Это также относится к другим сущностям, участвующим в процессе импорта/экспорта, таким как <a class="reference-link" href="../Basic%20Concepts%20and%20Features/Notes/Attachments.md">Вложения</a>.

## Коллизии заметок

Поскольку ID заметки — это случайно генерируемое число фиксированной длины, согласно [принципу Дирихле](https://en.wikipedia.org/wiki/Pigeonhole_principle) существует вероятность, что вновь созданная заметка получит тот же ID, что и существующая заметка.

Поскольку ID заметки буквенно-цифровой и имеет длину 12, у нас есть $62^{12}$ уникальных ID. Однако поскольку мы генерируем их случайно, можно использовать калькулятор коллизий, например для [Nano ID](https://alex7kom.github.io/nano-nanoid-cc/?alphabet=0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz&size=12&speed=1000&speedUnit=hour), чтобы определить, что нам нужно создавать по 1000 заметок в час каждый час в течение 9 веков, чтобы иметь вероятность коллизии заметок не менее 1%.

Поэтому Trilium не предпринимает явных действий против потенциальных коллизий заметок, подобно другому ПО, использующему уникальные хеши, такому как [Git](https://stackoverflow.com/questions/10434326/hash-collision-in-git). Если бы коллизия теоретически произошла, наиболее вероятным исходом было бы замещение существующей заметки новой.
