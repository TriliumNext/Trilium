# Массовые действия
<figure class="image"><img style="aspect-ratio:1425/644;" src="Bulk Actions_image.png" width="1425" height="644"></figure>

Диалог _Массовые действия_ упрощает применение изменений к нескольким заметкам сразу — от простых действий, таких как добавление или удаление метки, до выполнения пользовательских скриптов.

## Взаимодействие

*   Первый шаг — выбор заметок в <a class="reference-link" href="../Basic%20Concepts%20and%20Features/UI%20Elements/Note%20Tree.md">Дереве заметок</a>. Массовые действия можно применить:
    *   К одной заметке (и потенциально её дочерним заметкам), просто щёлкнув по ней (левой или правой кнопкой мыши).
    *   К нескольким заметкам. Как это сделать, см. <a class="reference-link" href="../Basic%20Concepts%20and%20Features/UI%20Elements/Note%20Tree/Multiple%20selection.md">Множественный выбор</a>.
*   Щёлкните правой кнопкой в <a class="reference-link" href="../Basic%20Concepts%20and%20Features/UI%20Elements/Note%20Tree.md">Дереве заметок</a> и выберите _Дополнительно_ → _Применить массовые действия_.
*   Раздел _Выбранные заметки_ вверху диалога перечисляет заметки, к которым применяются действия. Когда выбрано много заметок, показываются только первые несколько; нажмите _+N ещё_, чтобы показать остальные.
    *   Чтобы исключить заметку, не меняя выбор в дереве заметок, нажмите кнопку <span class="tn-icon bx bx-x"></span> в её записи. Последнюю оставшуюся заметку удалить нельзя.
*   По умолчанию затрагиваются только выбранные заметки. Чтобы включить также всех потомков заметок, включите _Включить потомков выбранных заметок_. Количество затрагиваемых заметок, показанное под этой опцией, обновляется при изменении.
*   Чтобы добавить действие, нажмите _Добавить действие_ (<span class="tn-icon bx bx-plus"></span>) внизу раздела _Выбранные действия_ и выберите его из меню. Наведение на пункт показывает краткое описание того, что он делает; подробное описание каждого доступно в следующем разделе.
    *   Каждое выбранное действие появляется записью в разделе _Выбранные действия_ с собственной конфигурацией.
    *   Чтобы удалить действие, просто нажмите кнопку <span class="tn-icon bx bx-x"></span> справа от него.
    *   Можно применять несколько действий одного типа, например добавление нескольких меток.
    *   Поля имени метки или отношения предлагают имена, уже используемые в базе данных, по мере ввода, помечая те, которым Trilium сам придаёт значение.
    *   Поле значения _Добавить метку_ и _Изменить значение метки_ предлагает значения, которые уже есть у указанной метки в базе данных.
*   Когда все действия определены, нажмите кнопку _Применить к N заметкам_, чтобы запустить их все одновременно. Кнопка называет количество затрагиваемых заметок и остаётся отключённой, пока не добавлено хотя бы одно действие.
    *   Если у действия не заполнено нужное поле, например имя переименовываемой метки, диалог не выполняется и указывает на пустое поле.
*   Для удобства последняя конфигурация массовых действий сохраняется для дальнейшего использования и будет восстановлена при следующем открытии диалога.

## Действия

### Метки

Эти действия работают с <a class="reference-link" href="Attributes/Labels.md">Метками</a> заметки. Кроме _Добавить метку_, они затрагивают только метки, заданные непосредственно на заметке; наследуемые метки не изменяются.

*   **Добавить метку**
    *   Для каждой заметки создаётся [метка](Attributes/Labels.md) с указанным именем. Оставьте поле _Новое значение_ пустым, чтобы создать метку без значения, или заполните его, чтобы присвоить значение.
    *   Метка добавляется, даже если заметка уже имеет метку с тем же именем, поэтому в итоге у заметки будет обе. Чтобы вместо этого изменить значение существующей метки, используйте _Изменить значение метки_.
*   **Изменить значение метки**
    *   Для каждой заметки, если у неё есть [метка](Attributes/Labels.md) с указанным именем, её значение будет изменено на указанное. Оставьте поле _Новое значение_ пустым, чтобы создать метку без значения.
    *   Заметки без этой метки не затрагиваются.
*   _**Переименовать метку**_
    *   Для каждой заметки, если у неё есть [метка](Attributes/Labels.md) с указанным именем, она будет переименована/заменена меткой с новым именем. Значение метки (если есть) сохраняется.
    *   Заметки без этой метки не затрагиваются.
*   **Удалить метку**
    *   Для каждой заметки, если у неё есть метка с указанным именем, она будет удалена (независимо от того, есть ли у неё значение).
    *   Заметки без этой метки не затрагиваются.

### Отношения

Эти действия работают с <a class="reference-link" href="Attributes/Relations.md">Отношениями</a> заметки. Кроме _Добавить отношение_, они затрагивают только отношения, заданные непосредственно на заметке; наследуемые отношения не изменяются.

*   **Добавить отношение**
    *   Для каждой заметки будет создано отношение, указывающее на заданную заметку.
    *   Отношение добавляется, даже если заметка уже имеет отношение с тем же именем.
*   **Изменить цель отношения**
    *   Для каждой заметки будет изменено отношение, чтобы оно указывало на вновь заданную заметку.
    *   Заметки без этого отношения не затрагиваются.
*   **Переименовать отношение**
    *   Для каждой заметки, если у неё есть отношение с указанным именем, оно будет переименовано/заменено отношением с новым именем. Целевая заметка отношения сохраняется.
    *   Заметки без этого отношения не затрагиваются.
*   **Удалить отношение**
    *   Для каждой заметки, если у неё есть отношение с указанным именем, оно будет удалено.
    *   Заметки без этого отношения не затрагиваются.

### Заметки

*   **Переименовать заметку**
    *   Для каждой заметки её заголовок будет изменён на заданный.
    *   Заголовок может содержать выражения между `${` и `}`, которые подставляются для каждой заметки. Они могут читать свойства заметки, такие как `${note.title}`, `${note.noteId}` или `${note.type}`, и вызывать `getLabelValue('name')`, `getRelationValue('name')` или, для даты вроде `dateCreatedObj`, `format('…')`. Например:
        *   `NEW: ${note.title}` добавит всем заметкам префикс `NEW:`.
        *   `${note.dateCreatedObj.format('MM-DD:')}: ${note.title}` добавит к заголовкам заметок дату их создания (в формате месяц-день).
    *   Разрешены только доступ к свойствам и перечисленные методы, не произвольный JavaScript. По мере ввода поле дополняет выражения, подчёркивает недопустимые и показывает итоговый заголовок для первой выбранной заметки.
*   **Переместить заметку**
    *   Каждая заметка будет перемещена в указанную родительскую заметку.
    *   Заметка с несколькими родителями вместо этого клонируется в новую родительскую заметку, так как неясно, какое из её местоположений удалять.
    *   Заметка, которую нельзя разместить там (например, родитель целевой заметки), остаётся на месте.
    *   Как альтернатива для менее сложных ситуаций, заметки можно перемещать прямо из <a class="reference-link" href="../Basic%20Concepts%20and%20Features/UI%20Elements/Note%20Tree.md">Дерева заметок</a> через вырезать → вставить или через контекстное меню.
*   **Конвертировать заметку**
    *   Это позволяет конвертировать заметку из одного типа в другой:
        *   **Текстовые заметки → Markdown-заметки** — каждая заметка <a class="reference-link" href="../Note%20Types/Text.md">Текст</a> конвертируется в <a class="reference-link" href="../Note%20Types/Markdown.md">Markdown</a>-заметку. Поскольку Markdown не поддерживает все возможности форматирования текстовых заметок, часть форматирования может быть потеряна, а некоторые неподдерживаемые элементы могут быть даже отброшены.
        *   **Markdown-заметки → Текстовые заметки** — каждая <a class="reference-link" href="../Note%20Types/Markdown.md">Markdown</a>-заметка конвертируется в заметку <a class="reference-link" href="../Note%20Types/Text.md">Текст</a>.
    *   Для каждой конвертированной заметки автоматически сохраняется ревизия, позволяющая восстановить исходную или извлечь из неё недостающие элементы.
*   **Сохранить ревизию**
    *   Автоматически создаёт ревизию каждой заметки. Опционально ревизии можно присвоить имя. См. <a class="reference-link" href="../Basic%20Concepts%20and%20Features/Notes/Note%20Revisions.md">Ревизии заметки</a>.
*   **Удалить заметку**
    *   Каждая заметка будет удалена, включая все её клоны и любые дочерние заметки, не клонированные в другом месте.
    *   Удалённые заметки можно восстановить из _Последних изменений_, пока они не стёрты.
    *   Как альтернатива для менее сложных ситуаций, заметки можно удалять прямо из <a class="reference-link" href="../Basic%20Concepts%20and%20Features/UI%20Elements/Note%20Tree.md">Дерева заметок</a>, выбрав их и нажав <kbd>Delete</kbd>.
*   **Удалить ревизии заметок**
    *   Это навсегда сотрёт все <a class="reference-link" href="../Basic%20Concepts%20and%20Features/Notes/Note%20Revisions.md">Ревизии заметки</a> заметок. В отличие от удалённых заметок, стёртые ревизии восстановить нельзя.

### Прочее

*   **Выполнить скрипт**
    *   Для более сложных сценариев можно ввести JavaScript-выражение для применения нужных изменений.
    *   Скрипт выполняется на сервере один раз для каждой заметки, с этой заметкой как `note` и серверным script API как `api`. Поле дополняет оба по мере ввода и подчёркивает ошибки, как редактор серверной скриптовой заметки.
    *   Примеры:
        *   Чтобы добавить суффикс (`- suffix` в этом примере) к заголовку заметки:

            ```javascript
            note.title = note.title + " - suffix";
            ```
        *   Чтобы изменить атрибуты заметки на основе другого атрибута, например установить метку `#shareAlias` равной заголовку заметки:

            ```javascript
            note.setLabel("shareAlias", note.title)
            ```
