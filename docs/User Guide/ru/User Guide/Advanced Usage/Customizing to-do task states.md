# Настройка состояний задач списка дел
Trilium предлагает настраиваемые состояния задач списка дел (to-do). Чтобы настроить их, откройте <a class="reference-link" href="../Basic%20Concepts%20and%20Features/UI%20Elements/Options.md">Настройки</a> → _Текстовые заметки_ → _Связанные настройки_ → _Пользовательские состояния флажков для списков дел_. Альтернативно щёлкните правой кнопкой по флажку в редактируемой текстовой заметке и нажмите значок карандаша; в <a class="reference-link" href="../Installation%20%26%20Setup/Mobile%20Frontend.md">мобильном интерфейсе</a> значок карандаша находится в строке кнопки _Список ›_ списка дел.

> [!WARNING]
> Изменения вступают в силу только после перезапуска приложения.

## Создание нового состояния задачи

Нажмите значок плюса рядом с «Состояния задач» на панели слева, затем задайте детали состояния, как описано в следующем разделе.

## Редактирование состояния задачи

Выбор любого состояния, кроме «None» и «Done» (которые изменить нельзя), на боковой панели раскрывает следующие редактируемые поля:

*   _Значок_ (обязательно): символ, показываемый внутри флажка. Значок выбирается так же, как для любой обычной заметки, в том числе из пользовательских наборов значков.
*   _Название_ (обязательно): имя состояния задачи, показываемое в интерфейсе. Например: «Doing», «Отложено».
*   _Идентификатор_ (обязательно): короткое имя состояния, использующее только буквы, цифры, «`-`» и «`_`». Он хранится как метаданные в разметке заметки и служит для идентификации состояния задачи. Два состояния задач не могут иметь один и тот же идентификатор.
    Добавляйте префикс «`_`» или «`-`» к идентификаторам своих пользовательских состояний, чтобы избежать конфликтов с состояниями, которые могут появиться в будущих версиях Trilium.
*   _Символ Markdown_: один символ, используемый для представления состояния в синтаксисе Markdown. Например, «`#`» создаёт состояние задачи, которое можно применить в Markdown как « `- [#]` ». Убедитесь, что этот символ не используется другим состоянием задачи.
*   _Считается выполненным_: если отмечено, задача считается выполненной.
*   _Цвет_: цвет флажка. Его светлота и насыщенность автоматически подстраиваются под текущую цветовую схему или тему.
*   _Скрыто из панели инструментов_: состояние не перечисляется в интерфейсе. Полезно, когда нужно, чтобы существующие заметки продолжали корректно отображать это состояние, но больше не требуется применять его самостоятельно.

> [!NOTE]
> Детали определения задач проверяются при запуске. При обнаружении ошибок показывается всплывающее уведомление с деталями, и затронутое определение задачи игнорируется.

## Изменение порядка состояний задач

Чтобы изменить порядок, в котором состояния задач появляются в интерфейсе и при переключении между ними с клавиатуры, просто измените порядок состояний на боковой панели (или в панели дерева, если это так).

## Удаление состояний задач

Любое состояние задачи, кроме «None» и «Done», можно удалить.

После удаления элементы списка дел, использовавшие это состояние, больше не будут показывать пользовательский флажок. Они откатываются либо к состоянию «None», либо к «Done» в зависимости от настройки состояния «Считается выполненным». Идентификатор и название остаются сохранены в заметке, пока вы не установите флажок в новое состояние.

## Перенос заметок с пользовательскими состояниями задач между экземплярами базы данных Trilium

Экспорт заметок в другой экземпляр базы данных Trilium сохраняет состояния задач элементов списка дел, но не включает пользовательские определения задач. В результате целевой экземпляр не будет знать, как отобразить флажок, пока вы не создадите там состояние задачи с тем же идентификатором и символом Markdown.

> [!NOTE]
> Это известное ограничение текущей версии. Если сообществу будет достаточно интересен более простой перенос заметок между экземплярами базы данных Trilium, команда Trilium может рассмотреть улучшенный механизм определения состояний.
