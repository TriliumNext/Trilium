# Продвигаемые атрибуты
<figure class="image image_resized" style="width:61.4%;"><img style="aspect-ratio:938/368;" src="Promoted Attributes_image.png" width="938" height="368"></figure>

Продвигаемые атрибуты — это [атрибуты](../Attributes.md), которые отображаются в интерфейсе заметно, что позволяет легко их просматривать и редактировать.

Продвигаемые атрибуты показываются под <a class="reference-link" href="../../Basic%20Concepts%20and%20Features/Notes/Title.md">Заголовком</a> заметки, в сворачиваемом разделе. Для заметок во всю высоту, таких как <a class="reference-link" href="../../Note%20Types/Canvas.md">Холст (Canvas)</a>, продвигаемые атрибуты по умолчанию свёрнуты, чтобы освободить место.

Один из способов видеть продвигаемые атрибуты — как форму с несколькими полями. Каждое поле — обычный атрибут; единственная разница в том, что они появляются на самой заметке.

Атрибуты могут быть весьма полезны, так как позволяют выполнять запросы, автоматизацию скриптами и т.д., но они также неудобно скрыты. Это даёт возможность выбрать несколько важных атрибутов и вывести их пользователю на передний план.

## Определение атрибута

<figure class="image image-style-align-right image_resized" style="width:50%;"><img style="aspect-ratio:885/742;" src="2_Promoted Attributes_image.png" width="885" height="742"></figure>

Чтобы иметь продвигаемые атрибуты, нужен способ их определить.

Технически атрибуты — это пары «имя-значение», где и имя, и значение являются строками.

_Определение атрибута_ задаёт, как это значение следует интерпретировать:

*   Это просто строка или дата?
*   Разрешать ли несколько значений или нет?
*   Следует ли _продвигать_ атрибут или нет?

## Типы атрибутов

Определения атрибутов имеют специальное поле типа, которое изменяет то, как значение редактируется в разделе продвигаемых атрибутов.

Поддерживаются следующие типы:

*   _Текст_ — вариант по умолчанию, позволяет редактировать любой текст, как обычные метки без ассоциированного типа.
*   _Многострочный текст_ — похож на обычное текстовое поле, но отображается в большом текстовом поле, поддерживающем несколько строк.
*   _Число_ — отображается как поле числового ввода со стрелками вверх/вниз.
    *   Опционально _точность_ (precision), задающая, с каким шагом и с каким количеством десятичных знаков отображается значение.
*   _Флажок_, отображается как чекбокс для значения истина/ложь. В определении метки этот тип записывается как `boolean`.
*   _Список (Select)_ — предоставляет список определённых пользователем вариантов при редактировании.
    *   Список не фиксирован: новые варианты можно легко добавлять прямо из продвигаемого атрибута.
    *   Переименование варианта не изменяет существующие значения, так как значение хранится как текст. Рассмотрите [массовое переименование](../Bulk%20Actions.md).
    *   Элементы не имеют пользовательского цвета или значка. Это намеренно: списки задуманы лёгкими. Для более настраиваемого варианта рассмотрите использование <a class="reference-link" href="Relations.md">Отношений</a>, где элементами являются заметки, которые можно раскрасить и которым можно задать значок.
*   _Дата_ — предоставляет выбор даты.
*   _Дата и время_ — предоставляет выбор даты и времени.
*   _Время_ — предоставляет выбор времени.
*   _URL_ — предоставляет кнопку открытия веб-адреса в новом окне.
*   _Электронная почта_ — предоставляет кнопку быстрой отправки письма на этот адрес через приложение по умолчанию операционной системы.
*   _Телефон_ — предоставляет кнопку быстрого звонка на этот номер через приложение по умолчанию операционной системы.
*   _Цвет_ — предоставляет палитру и способ удалить значение.
*   _Отношение_ — указывает на другую заметку и использует <a class="reference-link" href="Relations.md">Отношения</a> вместо <a class="reference-link" href="Labels.md">Меток</a>.

> [!NOTE]
> Для атрибутов на основе меток эти типы не принудительны для системы атрибутов: изменение типа впоследствии не гарантирует, что значения в нём соответствуют типу (например, превращение текста в число).

## Несколько значений

Когда определение разрешает несколько значений, каждое значение показывается плашкой, а новое добавляется в поле после них. Нажмите <span class="tn-icon bx bx-x"></span> на плашке, чтобы удалить это значение.

*   Для свободных типов, таких как _Текст_, _Число_ или _Дата_, нажмите <kbd>Enter</kbd> (или покиньте поле), чтобы добавить набранное. Одно и то же значение можно добавить несколько раз, например два платежа одной суммы.
*   Для атрибутов _Список_, _Флажок_ и _Отношение_ значение выбирается из списка, а не набирается, и каждое можно выбрать только один раз.

## Создание нового определения продвигаемого атрибута

Чтобы создать новый продвигаемый атрибут:

1.  Перейдите к заметке.
2.  Откройте <a class="reference-link" href="../../Basic%20Concepts%20and%20Features/UI%20Elements/Right%20Sidebar/Attributes%20tab.md">Вкладку атрибутов</a> в <a class="reference-link" href="../../Basic%20Concepts%20and%20Features/UI%20Elements/Right%20Sidebar.md">Правой боковой панели</a>.
3.  Нажмите кнопку <span class="tn-icon bx bx-plus"></span> для верхнего раздела (_Собственные атрибуты_).
4.  Выберите _Добавить определение метки…_ или _Добавить определение отношения…_.
5.  Выберите имя — это будет имя метки или отношения, которое создаётся при редактировании продвигаемого атрибута.
6.  Убедитесь, что отмечен пункт _Продвигаемый_, чтобы отображать его вверху заметок.
7.  Опционально задайте _Псевдоним_, который будет отображаться рядом с продвигаемым атрибутом вместо имени атрибута. Обычно лучше выбрать «удобное» имя, так как оно может содержать пробелы и другие символы, недопустимые в именах атрибутов.
8.  Отметьте _Наследуемый_, чтобы применить его к этой заметке и всем её потомкам. Чтобы оставить его только для текущей заметки, снимите отметку.
9.  Нажмите _Сохранить и закрыть_, чтобы применить изменения.

Альтернативно продвигаемые атрибуты можно создавать из <a class="reference-link" href="../../Basic%20Concepts%20and%20Features/UI%20Elements/Status%20bar.md">Строки состояния</a>: перейдите к <span class="tn-icon bx bx-list-check"></span> (_Атрибуты_), нажмите кнопку <span class="tn-icon bx bx-plus"></span> и выберите _Добавить определение метки…_. Результирующий атрибут также можно копировать или писать вручную (хотя это не рекомендуется).

## Как на самом деле работают определения атрибутов

При создании нового определения продвигаемого атрибута создаётся соответствующая метка с префиксом `label` или `relation` в зависимости от типа определения:

```
#label:myColor(inheritable)="promoted,alias=Color,multi,color"
```

Единственное назначение определения атрибута — задать шаблон. Если атрибут был помечен как продвигаемый, он также отображается пользователю для удобного редактирования.

Таким образом, один атрибут — для значения, другой — для определения. Но заметьте: атрибут определения можно сделать [наследуемым](Attribute%20Inheritance.md), то есть он также применяется ко всем дочерним заметкам. В этом случае определение используется для всего поддерева, а «значения» атрибутов задаются для каждой заметки отдельно.

Значение также может наследоваться. Если у заметки нет собственного значения, поле, хранящее одно значение, показывает то, которое заметка наследует (от наследуемого атрибута на родительской заметке или из <a class="reference-link" href="../Templates.md">Шаблонов</a>). Изменение поля создаёт значение на самой заметке, которое имеет приоритет над наследуемым; значение родителя или шаблона остаётся как есть. Чтобы вернуться к наследуемому значению, удалите собственный атрибут заметки в разделе _Собственные атрибуты_.

## Использование системных атрибутов

Можно создавать продвигаемые атрибуты из системных атрибутов, чтобы иметь возможность легко их изменять.

Вот несколько практических примеров:

*   <a class="reference-link" href="../../Collections.md">Коллекции</a> уже используют эту практику, например:
    *   Календари добавляют «Start Date», «End Date», «Start Time» и «End Time» как продвигаемые атрибуты. Они отображаются в системные атрибуты, такие как `startDate`, которые затем интерпретируются представлением календаря.
    *   <a class="reference-link" href="../../Collections/Presentation.md">Презентация</a> добавляет продвигаемый атрибут «Background» для каждого слайда, чтобы его можно было легко настраивать.
*   Документация Trilium (которая редактируется в Trilium) использует продвигаемый атрибут, чтобы легко редактировать `#shareAlias` (см. <a class="reference-link" href="../Sharing.md">Публикация</a>) и формировать чистые URL.
*   Если вы постоянно редактируете определённый системный атрибут, например `#color`, просто создайте для него продвигаемый атрибут, чтобы упростить это.

### Обратное отношение

Некоторые отношения всегда возникают парами — мой любимый пример — семья. Если у вас есть заметка, представляющая мужа, и заметка, представляющая жену, между ними может существовать отношение `isPartnerOf`. Это двунаправленная связь: если отношение указывает от мужа к жене, всегда должно быть и обратное отношение от жены к мужу.

Другой пример — отношения родитель-ребёнок. Они тоже всегда возникают парами, но здесь это не одно и то же отношение: от родителя к ребёнку может называться `isParentOf`, а от ребёнка к родителю — `isChildOf`.

Определение отношения позволяет указать такое «обратное отношение»: для только что определённого отношения вы указываете, какое отношение является обратным. Заметьте, что во втором примере нужны два определения отношений: одно для `isParentOf`, определяющее `isChildOf` как обратное, и второе для `isChildOf`, определяющее `isParentOf` как обратное.

Внутренне это работает так: всякий раз при сохранении отношения с определённым обратным отношением проверяется, что это обратное отношение существует на целевой заметке отношения. Аналогично, при удалении отношения обратное отношение на целевой заметке также удаляется.
