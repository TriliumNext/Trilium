# Наследование атрибутов
Наследование — это процесс, при котором [метка](Labels.md) или [отношение](Relations.md) разделяется несколькими заметками, обычно в родительско-дочерних отношениях (или где угодно, если используются шаблоны).

## Стандартное наследование

В Trilium атрибуты могут автоматически наследоваться дочерними заметками, если для них установлен флаг `isInheritable` в значение `true`. Это означает, что атрибут (пара «ключ-значение») применяется к заметке и всем её потомкам.

Чтобы сделать атрибут наследуемым, просто используйте визуальный редактор <a class="reference-link" href="Labels.md">Меток</a> или <a class="reference-link" href="Relations.md">Отношений</a>. Альтернативно атрибут можно определить вручную: `#myLabel=value` превращается в `#myLabel(inheritable)=value`, когда он наследуемый.

Например, метку `archived` можно сделать наследуемой, что позволит скрыть целое поддерево заметок из поиска и других диалогов, применив эту метку на верхнем уровне.

Стандартное наследование заставляет все дочерние (и поддочерние) заметки иметь определённую метку или отношение. Если нужно, чтобы некоторые заметки не наследовали одну из меток, следует использовать _копирующее наследование_ или _наследование шаблонов_.

## Копирующее наследование

Копирующее наследование отличается от стандартного использованием префикса `child:` в имени атрибута. Этот префикс заставляет новые дочерние заметки автоматически получать определённые атрибуты родительской заметки. Эти атрибуты независимы от родителя и сохранятся, даже если заметку переместить в другое место.

Если у родительской заметки есть метка `#child:exampleAttribute`, все вновь созданные дочерние заметки (на один уровень глубже) получат метку `#exampleAttribute`. Это может быть полезно для задания свойств по умолчанию для заметок в определённом разделе.

Аналогично для отношений используйте `~child:myRelation`.

Из-за особенностей реализации копирующее наследование нельзя использовать для бесконечного каскада в иерархии. Для такого случая рассмотрите стандартное наследование или шаблоны.

### Цепочечное наследование

Можно определять метки сразу на нескольких уровнях глубины. Например, `#child:child:child:foo`, применённая к корневой заметке, создаст:

*   `#child:child:foo` у дочерних заметок первого уровня.
*   `#child:foo` у дочерних заметок второго уровня.
*   `#foo` у дочерних заметок третьего уровня.

Аналогично используйте `~child:child:child:foo` для отношений.

Учтите, что, как и в простом копирующем наследовании, изменения не применяются задним числом к существующим заметкам в иерархии — только к вновь создаваемым.

## Наследование шаблонов

Атрибуты также можно наследовать из <a class="reference-link" href="../Templates.md">Шаблонов</a>. Когда новая заметка создаётся по шаблону, она наследует атрибуты, определённые в этом шаблоне. Это особенно полезно для поддержания единообразия заметок, имеющих схожую структуру или функцию.
