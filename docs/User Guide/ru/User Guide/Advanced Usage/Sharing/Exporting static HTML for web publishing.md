# Экспорт статического HTML для веб-публикации
Как описано в <a class="reference-link" href="../Sharing.md">Публикации</a>, Trilium может выступать публичным сервером, на котором опубликованные заметки отображаются в режиме только для чтения. Хотя это может работать в большинстве случаев, это в целом не предназначено для высоконагруженных сайтов, а поскольку это сервер на Node.js, его потенциально можно эксплуатировать.

Другая альтернатива — генерировать статические HTML-файлы (как другие генераторы статических сайтов, такие как [MkDocs](https://www.mkdocs.org/)). Поскольку обычный HTML-экспорт в ZIP не содержит стилей и дополнительной функциональности, Trilium предоставляет способ экспортировать тот же макет и стиль, что и функция <a class="reference-link" href="../Sharing.md">Публикации</a>, в статические HTML-файлы.

Помимо повышенной безопасности, эти HTML-файлы также легко развёртывать на «бессерверных» платформах, таких как GitHub Pages или CloudFlare Pages, и очень легко кэшируются.

> [!TIP]
> Документация Trilium, доступная на [docs.triliumnotes.org](https://docs.triliumnotes.org/), собрана с помощью этой функции экспорта в статические HTML-файлы, которые затем автоматически развёртываются на CloudFlare Pages.
>
> Процесс [автоматизирован](https://github.com/TriliumNext/Trilium/blob/main/apps/edit-docs/src/build-docs.ts) импортом Markdown-документации и её экспортом скриптом в статический веб-формат.

## Отличия от обычной публикации

Помимо обычной <a class="reference-link" href="../Sharing.md">Публикации</a>, экспорт в статические HTML-файлы имеет несколько тонких отличий:

*   Структура URL другая. Если при обычной публикации это что-то вроде `example.com/share/noteid`, то здесь заметки следуют иерархической структуре, например `docs.triliumnotes.org/user-guide/concepts/navigation/tree-concepts`.
*   `favicon.ico` не обрабатывается автоматически — его нужно вручную добавить на сервер после генерации экспорта.
*   «Последнее обновление» для заметок недоступно.
*   Поиск работает немного иначе, так как обычный требует активного API. В статическом экспорте поиск всё же работает, но использует другой механизм, поэтому результаты могут отличаться.

## Отличия от обычного .zip-экспорта

*   Имена файлов/URL будут предпочитать `shareAlias` для чистых URL.
*   Для экспорта требуется работающий веб-сервер, так как страницы не будут корректно отображаться при локальном доступе через веб-браузер из-за использования модульных скриптов.
*   Структура каталогов также немного другая:
    *   Обычный HTML-экспорт даёт индексный файл и один каталог.
    *   Вместо этого при статическом экспорте верхний корневой уровень становится индексным файлом, а дочерние каталоги находятся в корне.
    *   Это позволяет легко публиковать на сайте, не вынуждая всё, кроме корневой заметки, находиться в подкаталоге.

## Локальное тестирование

Как упоминалось ранее, экспортированные статические страницы требуют веб-сайта для работы. Для локального тестирования нужно использовать веб-сервер.

Один из примеров — основанный на Node.js [`http-server`](https://www.npmjs.com/package/http-server), который можно установить через:

```
npm i -g http-server
```

После установки просто:

1.  Распакуйте экспортированный .zip-файл.
2.  Внутри распакованного каталога запустите `http-server`.
3.  Откройте указанный адрес (например, [http://localhost:8080](http://localhost:8080)).
