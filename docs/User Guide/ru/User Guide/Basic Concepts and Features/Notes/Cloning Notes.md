# Клонирование заметок
## Мотивация

Ключевая возможность Trilium — структурировать ваши заметки в иерархическую древовидную структуру.

Ожидается, что у вас будет разработанная и глубокая иерархия заметок — каждое поддерево будет представлять более уточнённый и специализированный взгляд на вашу базу знаний.

Это довольно мощный подход, но он несёт скрытое допущение, что каждая «подтема» «принадлежит» одному родителю. Проиллюстрирую это примером — скажем, моя базовая структура такова:

*   Технологии
    *   Программирование
        *   Kotlin
        *   JavaScript
    *   Операционные системы
        *   Linux
        *   Windows

Теперь я начинаю изучать [Bash](https://en.wikipedia.org/wiki/Bash_\(Unix_shell\)) и хочу создать заметки, относящиеся к этой теме. Но теперь я сталкиваюсь с проблемой, куда это отнести. Проблема в том, что Bash — это и язык программирования, и инструмент (командная оболочка), очень тесно связанный с Linux. Кажется, он принадлежит обоим, я не могу (и не хочу) выбрать один вместо другого.

## Решение

Решение показанной выше проблемы — позволить заметкам иметь несколько родителей.

Я называю это «клонами», но это немного вводит в заблуждение — нет ни оригинала, ни клонированной заметки — заметки в обеих родительских категориях идентичны.

Ещё одна вводящая в заблуждение вещь в «клонировании» — она подразумевает, что была сделана копия заметки. Это не совсем так: сама заметка остаётся в одном оригинале, она просто упоминается в нескольких местах иерархии дерева. Поэтому изменение её в одной категории изменяет её во всех остальных, потому что это всё та же заметка.

Вот итоговая структура с клонированием:

*   Технологии
    *   Программирование
        *   Kotlin
        *   JavaScript
        *   Bash
            *   некоторые подзаметки …
    *   Операционные системы
        *   Linux
            *   Bash
                *   некоторые подзаметки …
        *   Windows

Теперь поддерево «Bash» появляется в нескольких местах иерархии. Оба поддерева Bash — одно и то же и содержат те же подкатегории и заметки.

### Демонстрация

![](Cloning%20Notes_create-clone.gif)

В демонстрации вы можете видеть, как клон может быть создан через контекстное меню. Это также можно сделать через диалог «Добавить ссылку» или с помощью [сочетаний клавиш](../Keyboard%20Shortcuts.md) <kbd>Ctrl</kbd>+<kbd>C</kbd> и <kbd>Ctrl</kbd>+<kbd>V</kbd>.

Вы можете просмотреть список всех доступных клонов:

*   В <a class="reference-link" href="../UI%20Elements/Status%20bar.md">Строке состояния</a>, отыскав значок <span class="tn-icon bx bx-directions"></span>.
*   На <a class="reference-link" href="../UI%20Elements/Right%20Sidebar/Connections%20tab.md">Вкладке связей</a> <a class="reference-link" href="../UI%20Elements/Right%20Sidebar.md">Правой боковой панели</a>, посмотрев раздел _Пути заметки_.

В <a class="reference-link" href="../UI%20Elements/Note%20Tree.md">Дереве заметок</a>, на десктопе и на мобильных устройствах, заголовок клонированной заметки сопровождается значком <span class="tn-icon bx bxs-directions"></span>, чтобы легко было видеть, что заметка также размещена в каком-то другом месте. Опубликованная заметка сопровождается значком <span class="tn-icon bx bx-share-alt"></span> таким же образом.

## Удаление заметок/клонов

С клонами может быть не сразу очевидно, как работает удаление.

Если вы попытаетесь удалить заметку, это работает так:

1.  если у заметки есть несколько клонов, удаляется только этот клон, а сама заметка (и её остальные клоны) остаются как есть.
2.  если у этой заметки нет других клонов, заметка удаляется
    *   весь процесс, начиная с п. 1, запускается для всех дочерних заметок заметки
