# Сортировка заметок
Trilium может отсортировать дочерние заметки заметки один раз, используя диалог _Сортировать по…_, или держать их отсортированными постоянно, используя метку `#sorted`. Оба сортируют по тем же критериям: заголовок, дата создания или изменения или значение метки на дочерних заметках, и оба могут сочетать несколько из них в уровни сортировки.

## Одноразовая сортировка диалогом

Чтобы отсортировать потомков заметки один раз, щёлкните правой кнопкой по ней в <a class="reference-link" href="../UI%20Elements/Note%20Tree.md">Дереве заметок</a> и выберите _Сортировать по…_, или выберите её и нажмите <kbd>Alt</kbd>+<kbd>S</kbd>. Порядок применяется только к существующим дочерним заметкам; заметки, добавленные позже, размещаются там, где они созданы.

Диалог состоит из:

*   _Критерии сортировки_, списка уровней. Каждый уровень сортирует по _Заголовку_, _Дате создания_, _Дате изменения_ или _Метке_ (за которой следует имя метки), _По возрастанию_ или _По убыванию_.
    *   Чтобы сортировать по нескольким критериям, выберите _Добавить уровень_. Первый уровень определяет порядок; следующие уровни решают только между заметками, которые предыдущие оставили равными (см. _Уровни сортировки_ ниже).
    *   Чтобы изменить порядок уровней, используйте кнопки <span class="tn-icon bx bx-up-arrow-alt"></span> и <span class="tn-icon bx bx-down-arrow-alt"></span>. Чтобы удалить уровень, используйте кнопку <span class="tn-icon bx bx-x"></span>.
*   _Папки сначала_, которое размещает заметки, имеющие собственных потомков, перед остальными. Когда первый уровень по убыванию, они размещаются внизу.
*   _Естественная сортировка_, которая сравнивает числа и символы по правилам языка (см. _Как сравниваются значения_ ниже). _Язык естественной сортировки_ задаёт код языка, например `zh-CN` для китайского.

Заметки с `#top` или `#bottom` остаются вверху или внизу, как при автоматической сортировке (см. _Закрепление заметок вверху или внизу_ ниже).

## Постоянная сортировка дочерних заметок

Чтобы держать потомков заметки отсортированными, добавьте на неё [метку](../../Advanced%20Usage/Attributes/Labels.md) `#sorted`. Trilium сортирует её дочерние заметки заново всякий раз, когда потомок добавляется или меняется и когда меняются метки сортировки.

| Метка | Описание |
| --- | --- |
| `#sorted` | Держит дочерние заметки отсортированными. Без значения сортирует по заголовку; со значением — по перечисленным им уровням (см. _Уровни сортировки_ ниже). `#sorted=off` выключает сортировку. |
| `#sortDirection` | `asc` (по умолчанию) или `desc`. Направление каждого уровня, который не задаёт своё собственное. |
| `#sortFoldersFirst` | Размещает заметки, имеющие собственных потомков, перед остальными, или после них, когда `#sortDirection` равен `desc`. |
| `#sortNatural` | Сравнивает числа по их значению, а не посимвольно, поэтому 2 идёт раньше 10. |
| `#sortLocale` | Код языка для `#sortNatural`, например `zh-CN` или `de`. |
| `#top` | На дочерней заметке: держит её вверху отсортированного родителя. |
| `#bottom` | На дочерней заметке: держит её внизу отсортированного родителя. |

Метки применяются к заметке, которая их несёт, и, когда сделаны [наследуемыми](../../Advanced%20Usage/Attributes/Attribute%20Inheritance.md), к каждой заметке ниже неё, поэтому одиночная `#sorted(inheritable)` сортирует целое поддерево. Заметка, созданная из [шаблона](../../Advanced%20Usage/Templates.md) с `#sorted`, тоже держит своих потомков отсортированными. Чтобы исключить часть такого поддерева, добавьте `#sorted=off` заметке, чьи потомки должны сохранять ручной порядок; чтобы исключить и всё ниже неё, сделайте эту метку тоже наследуемой.

## Уровни сортировки

Значение `#sorted` — разделённый запятыми список уровней, записанный как `orderBy` [поиска](../Navigation/Search.md). Каждый уровень — один из:

*   Метки на дочерних заметках, записанные с `#`, например `#priority`.
*   Одно из свойств `title`, `dateCreated` и `dateModified`, записанное без `#`.
*   `folders`, которое есть только у заметок с собственными потомками (см. _Группировка_ ниже).

За уровнем может следовать `asc` или `desc`, чтобы задать его направление; иначе он следует `#sortDirection`.

Дочерние заметки сортируются по первому уровню. Заметки, равные на этом уровне, сортируются по второму уровню и так далее. Заметки, равные на каждом уровне, сортируются по заголовку в направлении `#sortDirection`.

Дочерняя заметка, не имеющая метки уровня, размещается после каждого потомка, имеющего её, в каком бы направлении ни работал уровень. Между двумя заметками, у которых её обеих нет, решает следующий уровень.

Например, `#sorted="#priority desc, #dueDate"` на родителе с этими потомками:

| Дочерняя заметка | Метки |
| --- | --- |
| Отчёт о книге | `#priority=2` `#dueDate=2026-11-01` |
| Продукты | `#priority=1` |
| Налоги | `#priority=2` `#dueDate=2026-10-25` |
| Идеи | нет |

сортирует их как _Налоги_, _Отчёт о книге_, _Продукты_, _Идеи_. Высший приоритет идёт первым; у _Налогов_ и _Отчёта о книге_ он общий, поэтому между ними решает более ранняя дата сдачи. У _Идей_ нет приоритета, и она идёт последней.

Значение, которое является единственным именем без `#`, читается так, как делали старые версии: `title`, `dateCreated` или `dateModified` — это свойство, а любое другое имя — метка, поэтому `#sorted=myOrder` сортирует по метке `#myOrder` потомков.

> [!WARNING]
> Начиная с v0.107.0, метка в значении `#sorted` с более чем одним уровнем или с направлением должна записываться с `#`. В v0.106.0 имена записывались голыми, как в `#sorted="priority desc, dueDate"`; такое значение теперь читает оба имени как несуществующие свойства, и заметки откатываются к сортировке по заголовку. Добавьте `#` перед каждым именем метки, чтобы восстановить её.

## Группировка через `first` и `last`

Метка, за которой следует `first` или `last`, не сортирует по значению метки: она размещает дочерние заметки, имеющие эту метку с любым значением, перед остальными или после них. Следующие уровни затем сортируют внутри каждой группы. Группировка игнорирует `#sortDirection`.

Например, `#sorted="#archived last, #priority desc"` на родителе с этими потомками:

| Дочерняя заметка | Метки |
| --- | --- |
| Старый проект | `#archived` `#priority=3` |
| Черновик | `#priority=1` |
| Запуск | `#priority=3` |
| Заметки встречи | нет |

сортирует их как _Запуск_, _Черновик_, _Заметки встречи_, _Старый проект_. [Архивная заметка](Archived%20Notes.md) идёт ниже всех остальных несмотря на высокий приоритет, а остальные сортируются по приоритету.

`folders first` и `folders last` группируют заметки, имеющие собственных потомков. Уровень `folders` без `first` или `last` также размещает их первыми в любом направлении. `#sortFoldersFirst` — сокращение для уровня `folders first`; он не имеет эффекта, когда `#sorted` уже содержит `folders`.

## Закрепление заметок вверху или внизу

Дочерняя заметка с `#top` остаётся вверху отсортированного родителя, а с `#bottom` — внизу, что бы ни говорили уровни `#sorted`. Когда несколько заметок имеют `#top`, они сортируются по значению метки, поэтому `#top=1` идёт перед `#top=2`, а `#top` без значения идёт первой. `#bottom` работает наоборот: последними идут `#bottom=2`, затем `#bottom=1`, затем `#bottom` без значения в самом конце.

`#sortFoldersFirst` размещает папки сразу после заметок `#top`.

Чтобы закреплять заметки внутри групп вместо всего списка, назовите `#top` и `#bottom` в `#sorted` на позиции, где они применяются. Например:

*   `#sorted="#archived last, #top first, #bottom last, title"` держит архивные заметки ниже всех остальных, включая имеющие `#bottom`. `#top` и `#bottom` затем применяются внутри архивной и неархивной групп по отдельности.
*   `#sorted="#archived last, #top first, #bottom last, folders first, title"` также размещает папки первыми внутри каждой группы. `#sortFoldersFirst` делает то же самое: его уровень `folders first` идёт сразу после последнего из `#top` и `#bottom`.
*   Записанные с `first` или `last`, `#top` и `#bottom` игнорируют свои значения. Чтобы упорядочить несколько закреплённых заметок по значению, добавьте уровень после них, например `#top first, #top, #bottom last, #bottom desc`.

## Как сравниваются значения

*   Значения сравниваются как текст, посимвольно, без учёта регистра. Даты в форме `YYYY-MM-DD` сортируются правильно, но числа — нет: `"10"` идёт раньше `"2"`. Либо дополняйте числа нулями (`02`, `10`), либо включайте `#sortNatural`.
*   С `#sortNatural` числа сравниваются по значению, а сравнение следует правилам языка, заданного `#sortLocale` (или языка по умолчанию), который также игнорирует акценты.
*   Заголовок заметки включает её <a class="reference-link" href="Cloning%20Notes/Branch%20prefix.md">Префикс ветви</a>, если он есть в этом родителе, как `prefix - title`.
*   Метка без значения всё равно считается присутствующей: она сортируется перед заметками, не имеющими метки, а среди имеющих её заметок — как наименьшее значение.
