# Внутреннее устройство
## Стратегия прогрессивного поиска

Trilium использует стратегию прогрессивного поиска, которая выполняет точное сопоставление первым, а затем добавляет нечёткое сопоставление при необходимости.

Поиск имеет три фазы:

1.  **Фаза 1 - Точное сопоставление**: При поиске Trilium сначала ищет точные совпадения ваших поисковых терминов. Это покрывает подавляющее большинство поисков (90%+) и возвращает результаты почти мгновенно.
2.  **Фаза 2 - Нечёткий запасной вариант**: Если Фаза 1 не находит достаточно качественных результатов (меньше 5 результатов с хорошими оценками релевантности), Trilium автоматически добавляет нечёткое сопоставление для поиска результатов с опечатками или вариантами написания.
3.  **Упорядочение результатов**: Точные совпадения всегда появляются перед нечёткими независимо от отдельных оценок. Это гарантирует, что при поиске «project» заметки, содержащие точное слово «project», будут появляться перед заметками, содержащими похожие слова, такие как «projects» или «projection».

### Поведение прогрессивного поиска

*   **Скорость**: Большинство поисков завершаются, используя только точное сопоставление
*   **Упорядочение**: Точные совпадения появляются перед нечёткими
*   **Запасной вариант**: Нечёткое сопоставление активируется, когда точные совпадения возвращают меньше 5 результатов
*   **Идентификация**: Результаты указывают, являются ли они точными или нечёткими совпадениями

## Производительность поиска

Спецификации системы поиска:

*   Лимит размера содержимого: 10 МБ на заметку (ранее 50 КБ)
*   Вычисления редакционного расстояния для нечёткого сопоставления
*   Бесконечная прокрутка в Быстром поиске

## Сокращения для меток и отношений

«Полный» синтаксис для поиска по меткам:

```
note.labels.publicationYear = 1954
```

Для отношений:

```
note.relations.author.title *=* Tolkien
```

Однако распространённые поиски по меткам и отношениям имеют сокращённый синтаксис:

```
#publicationYear = 1954
~author.title *=* Tolkien
```

## Разделение полнотекстовой и атрибутной частей

Синтаксис поиска позволяет сочетать полнотекстовый поиск с поиском по атрибутам. Например, `tolkien #book` содержит:

1.  Полнотекстовые токены - `tolkien`
2.  Атрибутные выражения - `#book`

Trilium определяет разделение между полнотекстовым поиском и поиском по атрибутам/свойствам, отыскивая определённые специальные символы или слова, обозначающие атрибуты и свойства (например, #, ~, note.). Если вам нужно включить их в полнотекстовый поиск, экранируйте их обратным слешем, чтобы они обрабатывались как обычный текст:

```
"note.txt" 
\#hash 
#myLabel = 'Say "Hello World"'
```

## Экранирование специальных символов

Специальные символы можно заключать в кавычки или экранировать обратным слешем для использования в полнотекстовом поиске:

```
"note.txt"
\#hash
#myLabel = 'Say "Hello World"'
```

Поддерживаются три типа кавычек: одинарные, двойные и обратные.

## Приведение типов

Значения меток технически являются строками, но могут приводиться к числам для сравнения:

```
note.dateCreated =* '2019-05'
```

Это находит заметки, созданные в мае 2019 года. Числовые операторы, такие как `#publicationYear >= 1960`, преобразуют строковые значения в числа для сравнения.
