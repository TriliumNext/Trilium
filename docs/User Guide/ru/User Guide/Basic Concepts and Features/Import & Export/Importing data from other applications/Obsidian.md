# Obsidian
Хотя Obsidian поддерживался косвенно через стандартный импорт <a class="reference-link" href="../Markdown.md">Markdown</a>, структура его хранилища достаточно специфична, чтобы оправдать собственный выделенный канал импорта.

## Процесс импорта

Первый шаг — получить .zip вашего хранилища Obsidian:

1.  Сначала определите, где расположено ваше хранилище Obsidian. Проще всего открыть Obsidian и щёлкнуть правой кнопкой по названию хранилища внизу левой боковой панели, а затем выбрать _Показать в проводнике системы_.
2.  В проводнике системы щёлкните правой кнопкой по каталогу, содержащему ваше хранилище Obsidian, и сожмите его в ZIP-файл (например, в Windows: _Сжать в_ → _ZIP_).

> [!TIP]
> При создании ZIP вы можете заархивировать как внешнюю папку хранилища, так и его содержимое — Trilium автоматически определит положение хранилища в архиве по каталогу `.obsidian`.

Затем в Trilium Notes:

1.  В <a class="reference-link" href="../../UI%20Elements/Note%20Tree.md">Дереве заметок</a> щёлкните правой кнопкой и выберите _Импортировать в заметку_.
2.  В разделе _Импорт из_ выберите <span class="tn-icon tn-brand tn-brand-obsidian"></span> _Obsidian_.
3.  Загрузите ZIP, полученный на предыдущем шаге.

Альтернативно, просто перетащите .zip-архив в <a class="reference-link" href="../../UI%20Elements/Note%20Tree.md">Дерево заметок</a>, и Trilium автоматически распознает его как импорт Obsidian, если присутствует каталог `.obsidian`. Если его нет, следуйте предыдущим шагам.

## Поддерживаемые возможности

Следующие возможности сохраняются Trilium в процессе импорта:

*   Иерархия папок сохраняется.
*   Базовое Markdown-форматирование (полужирный, курсив, подчёркивание, зачёркивание, заголовки).
*   Специфическое форматирование Obsidian (выделение).
*   <a class="reference-link" href="../../../Note%20Types/Text/Lists.md">Списки</a>
*   Списки дел (to-do)
*   <a class="reference-link" href="../../../Note%20Types/Text/Images.md">Изображения</a> и <a class="reference-link" href="../../Notes/Attachments.md">Вложения</a>
    *   Не-Markdown файлы в хранилище по умолчанию обрабатываются как вложения, если на них ссылается хотя бы одна заметка.
    *   В противном случае они будут импортированы как заметки <a class="reference-link" href="../../../Note%20Types/File.md">Файл</a>.
*   Трансклюзии конвертируются в <a class="reference-link" href="../../../Note%20Types/Text/Include%20Note.md">Включение заметки</a> или <a class="reference-link" href="../../../Note%20Types/Text/Images.md">Изображения</a> (в зависимости от типа).
*   <a class="reference-link" href="../../../Note%20Types/Text/Math%20Equations.md">Математические формулы</a> (встроенные или блочные)
*   <a class="reference-link" href="../../../Note%20Types/Text/Developer-specific%20formatting/Code%20blocks.md">Блоки кода</a> с попыткой восстановить язык по мере возможности.
*   Ссылки между страницами конвертируются в <a class="reference-link" href="../../../Note%20Types/Text/Links/Internal%20(reference)%20links.md">внутренние (ссылочные) ссылки</a>.
*   Выноски (callouts) конвертируются в [Замечания (admonitions)](../../../Note%20Types/Text/Block%20quotes%20%26%20admonitions.md) Trilium.
    *   У Obsidian гораздо больше типов выносок (`tldr`, `question`, `attention`) — все они сопоставляются одному из существующих типов замечаний Trilium (например, Note, Tip, Important).
    *   Пользовательские заголовки сохраняются и показываются полужирной строкой вверху замечания, так как в Trilium нет понятия заголовка замечания.
    *   Сворачиваемые выноски импортируются развёрнутыми и без маркера сворачивания.
*   Заметки, созданные сообщественным плагином [_Excalidraw_](https://github.com/zsviczian/obsidian-excalidraw-plugin) для Obsidian, конвертируются в <a class="reference-link" href="../../../Note%20Types/Canvas.md">Холст</a> (та же лежащая в основе технология).
    *   Обратите внимание, что пользовательские возможности, добавленные этим плагином, поддерживаться не будут.
*   Дата модификации сохраняется через информацию, полученную из .zip-архива; дата создания невосстановима, поэтому она устанавливается равной дате модификации.

## Свойства (Properties)

Свойства — это аналог Obsidian для <a class="reference-link" href="../../../Advanced%20Usage/Attributes/Promoted%20Attributes.md">Продвигаемых атрибутов</a>. Одно из ключевых различий между ними — где хранится информация о свойстве (т.е. имя и тип): в Obsidian всё хранится на уровне хранилища и разделяется между всеми заметками, тогда как в Trilium каждая страница может иметь индивидуальные продвигаемые атрибуты, разделяемые через <a class="reference-link" href="../../../Advanced%20Usage/Templates.md">Шаблоны</a> или <a class="reference-link" href="../../../Advanced%20Usage/Attributes/Attribute%20Inheritance.md">Наследование атрибутов</a>.

Ещё одно важное различие: продвигаемые атрибуты в Trilium всегда отображаются, даже если пусты. В Obsidian они просто предлагаются при создании нового свойства.

Чтобы примирить все эти различия, свойства конвертируются в <a class="reference-link" href="../../../Advanced%20Usage/Attributes/Promoted%20Attributes.md">Продвигаемые атрибуты</a> на уровне заметки.

Поддерживаются следующие типы заметок:

| Тип Obsidian | Trilium |
| --- | --- |
| Text или не задан | Однозначная метка `text` |
| Number | Однозначная метка `number` |
| Multitext | Многозначная метка `text` |
| Checkbox | Метка `boolean` (`true`/`false`). |
| Date | `date` |
| Date & Time | `datetime` |

### Специальные свойства

В Obsidian есть несколько зарезервированных имён свойств, которые в Trilium также обрабатываются иначе:

*   `tags`, где каждый тег превращается в собственную [метку](../../../Advanced%20Usage/Attributes/Labels.md) (например, `#one`, `#two` при `tags: [ one, two ]`).
*   `aliases` просто сопоставляются отдельным меткам `#alias`
*   `cssclasses`, `publish`, `permalink` игнорируются.

## Ограничения

*   Комментарии (синтаксис `%%`) просто удаляются.
*   Функциональность _bases_ Obsidian не сохраняется.
    *   Ближайший аналог в Trilium — <a class="reference-link" href="../../../Collections.md">Коллекции</a>, но они работают принципиально иначе, так как bases не хранят конкретные заметки, а действуют скорее как <a class="reference-link" href="../../../Note%20Types/Saved%20Search.md">Сохранённый поиск</a> с видом коллекции.
    *   Поскольку формат запросов base сильно отличается от синтаксиса <a class="reference-link" href="../../Navigation/Search.md">Поиска</a> Trilium, вряд ли они когда-либо будут поддержаны.
    *   При обнаружении base она просто игнорируется в импорте.
*   Холсты (canvases) не импортируются.
    *   Теоретически они могли бы сопоставляться либо <a class="reference-link" href="../../../Note%20Types/Canvas.md">Холсту</a>, либо <a class="reference-link" href="../../../Note%20Types/Relation%20Map.md">Карте отношений</a>, но они слишком различны для примирения.
*   Ссылки
    *   Ссылки на конкретный заголовок в другой заметке по-прежнему будут указывать на нужную заметку, но якорь заголовка будет отброшен.
    *   Висячие ссылки (указывающие на несуществующую заметку) и неоднозначные ссылки (одно базовое имя в 2+ заметках) разворачиваются в обычный текст.
