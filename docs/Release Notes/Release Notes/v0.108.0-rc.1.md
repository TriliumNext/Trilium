Links can now point at a heading or an anchor instead of a whole note, in text and Markdown notes as well as in PDF, EPUB, Word and OpenDocument files. The Outline tab lists the headings of those files too, with a filter and a way to copy a reference to any of them. Text notes also gain collapsible headings, aside blocks and a scrollbar that marks search results and colored text.

Vim users can now bring their habits to text notes, with a Vim mode that understands paragraphs, lists, tables and embedded content. Trilium also starts noticeably faster, on desktop and on phones.

Android gets its first stable release, with the APK attached below. It syncs with a server of the same version and installs beside the nightly build, so moving from the nightly means syncing again or restoring a backup.

## 💡 Key highlights

### Vim mode in text notes

Code notes have had Vim key bindings for years, but text notes, where most of the writing in Trilium happens, had none. For anyone used to Vim, every text note meant putting that habit aside and going back to the mouse and the arrow keys. Vim users have asked for this since 2021, and now the time has finally come to make it real: text notes have a Vim mode of their own. It runs on the same Vim engine as code notes, so the commands work as they do there, and it understands the structure of rich text: a paragraph, a heading, a list item, a table cell and a line of code are each a line; an image, a diagram or an included note is one line that `j` and `k` stop on and `dd` deletes; and yanked text keeps its bold, links and colors when it is put back. Insert mode is the editor as it was, with its formatting shortcuts, slash commands and Markdown autoformatting.

Motions, operators, text objects, counts, repeating with `.`, registers, marks, macros, search and `:s` all work, inside included notes too. Trilium commands join them: `:w` saves the note, `:q` closes it, `gf` follows the link under the cursor, `za` folds a heading, list item or collapsible block, `:sort` sorts lines, `:ck` runs any editor command, and `"+y` copies to the system clipboard with the formatting. The status bar shows the mode, the keys of a pending command and macro recording, and `:`, `/` and `?` open the command line in place of the breadcrumb. Zen mode keeps both.

Key hints help while you learn and stay quiet otherwise. Normal and Visual mode show their keys in the status bar, and a pause in the middle of a command shows the keys that can follow it. The command line completes command names with `Tab`, the search prompt tells how the pattern is read, and `Alt+F1` or a click on the mode lists every key. `Esc` in Normal mode switches between the keys and the breadcrumb, and the Key hints option turns them off.

Turn it on in Options → Text Notes → Features → Vim mode, on each device where you want it. The Vim badge in the status bar, or a `#vimMode` label, turns it on or off for a single note, and startup commands set up mappings such as `imap jk <Esc>`.

### A faster start, on desktop and on phones

Trilium now starts noticeably faster. It shows the launch bar, the tabs and the note tree first, and loads the rest only once you use it. This applies to phones too.

The difference is largest on slower devices. Simulating a slower device on a 20 Mbit/s connection, a note is ready to edit in 2.5 s instead of 5.2 s on desktop, and in 2.3 s instead of 4.8 s on a phone. On a fast computer, it is ready about 30% sooner.

### Link directly to headings within notes

When you create a link to a note, you can choose a heading so the link opens at that section. This works with text notes, Markdown, PDF, EPUB, ODT, and DOCX.


## 🚨 Breaking changes

*   For theme developers: the `--background-material` CSS variable no longer has an effect. Trilium now chooses the Mica or vibrancy backdrop itself, from the layout, and applies it only to the Next themes and to custom themes based on them with `#appThemeBase`. The `setBackgroundMaterial()` and `setVibrancy()` methods of `window.electronApi.window` were removed.

## 🔒️ Security improvements

1.  On the desktop app, a web page could send notes to the web clipper endpoint, and with DNS rebinding could plant a script that ran when the app next started.
2.  A visitor of a shared note could use the share search to read the titles, labels and content of notes that were never shared, one character at a time.
3.  On the desktop app with network access enabled, setting the initial password is now restricted to the desktop app itself.
4.  Note icons are validated more strictly before they are displayed.
5.  The desktop application no longer opens program files from a note without asking.
6.  Safe import also disables scripts and other active content set through Markdown front matter, Evernote tags and Notion, Anytype or Obsidian properties.
