## 💡 Key highlights

*   The Docker image has been reworked so that it can run as a non-root user. Look for the corresponding section in the [Docker setup documentation](https://docs.triliumnotes.org/user-guide/setup/server/installation/docker). ([#5790](https://github.com/TriliumNext/Trilium/issues/5790))
*   LLM
    *   ChatGPT Codex subscriptions can now be used for Trilium's AI integration. There's also a free plan.
    *   🔍️ **Use custom search engines**  
        Especially useful for local LLM usage or even cloud providers that don't have a builtin search (DeepSeek): cloud ones (Brave Search, Tavily, Exa, Serper, Perplexity) and SearXNG as a self-hosted solution.
    *   **🛡️ Permissions for AI tool calls**  
        Before the AI reads or changes your notes, the chat shows what it is about to do, and you can allow or deny it. If you trust a tool, you can allow it for the rest of the chat. The Tools menu also has three modes: always ask, ask only before changes, or never ask. This works with both API keys and subscription providers such as Claude Code, Codex, GitHub Copilot and Antigravity.
*   The contextual menu has been rewritten from scratch, bring in some benefits such as [keyboard navigation](https://github.com/TriliumNext/Trilium/issues/1166), better accessibility and fixing issues such as [clipping](https://github.com/TriliumNext/Trilium/issues/5294). The note tree menu has also been compacted a bit to reduce mental overload. ([#5493](https://github.com/TriliumNext/Trilium/issues/5493))
*   [The note autocomplete has been rewritten from scratch](https://github.com/TriliumNext/Trilium/issues/5134) with a modernized design, the command palette, link/relation pickers, @-mentions in text notes and Markdown notes and attribute value suggestions.
*   [PDF: copy a reference link that brings you to a page or an annotation.](https://github.com/TriliumNext/Trilium/issues/8635)
*   The relation map has been modernized, with a nicer design for the cards (displaying icons and respecting the note colors) and relations. Clicking on a note no longer closes the map and instead opens a panel to the side and the creation process has also been improved.
*   Redesigned the mobile layout for iOS with an iOS 26-inspired design.
*   Both the iOS and Android mobile versions now have a new navigation system that works without a sidebar.
*   The presentation collection got a refresh
    *   Slides keep a 16:9 shape and fit their content as the pane changes.
    *   Web view notes can show their pages as presentation slides.
    *   Board and table collections can fill a slide with their cards or rows.
    *   Text and canvas slides can be edited directly in the presentation.
    *   A slide sidebar lets presenters navigate and change the deck.
    *   Canvas and code previews follow the page's color scheme and saved content.
    *   Shared overlay controls can show menus and shortcuts in a consistent style.

## 🚨 Breaking changes

*   The old layout has been removed. It's been almost a year since the new layout was introduced and we believe it has been polished enough to see day-to-day use. For more information, see the [corresponding GitHub Discussions post](https://github.com/orgs/TriliumNext/discussions/11891).
*   Multi-level `#sorted` values introduced in v0.106.0 must now write labels with `#`, as search's `orderBy` does: `#sorted="priority desc, dueDate"` becomes `#sorted="#priority desc, #dueDate"`. Values without `#` fall back to sorting by title. A single name (`#sorted=myOrder`) and property-only values (`dateModified desc, title`) are unaffected. See [Sorting Notes](https://docs.triliumnotes.org/user-guide/concepts/notes/sorting).
*   `POST /etapi/auth/login` now requires a code if TOTP is enabled. Check the API documentation for more information.
