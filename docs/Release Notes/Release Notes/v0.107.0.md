This is the release where a text note stops being a single document. Notes can be embedded, quoted and referenced inside other notes and edited where they appear, laid out in columns and tabs, and mixed with drawings, attached files and video. Tables in text notes get the tools they had been missing, from merged cells to sorting, and the old layout is gone, a year after the new one replaced it.

Around the editor, the parts of the app that everyone touches were rebuilt: the context menus and the note autocomplete, the full search and the jump dialog, the launch bar and the tree. Shared pages look like the app again and render collections with their own views, and the calendar and geo map collections get the properties dialogs the board already had.

The AI integration becomes something to trust with a real database: every tool call asks before it reads or changes a note, a ChatGPT Codex subscription can stand in for an API key, and local models get web search through a search engine of your choice. On phones, iOS has a new layout and both apps navigate without a sidebar.

## 💡 Key highlights

### The text editor became a block editor

A text note used to be a document: one body of rich text, with other notes reachable only through links. It is now a composition. A note can embed another note and let you edit it where it sits, quote a few of its blocks and keep the quote current, or point at one paragraph of it instead of at the whole note.

*   [Editable transclusion](https://github.com/TriliumNext/Trilium/pull/11926): an included text or code note is edited inside the host note with the full editor, and one undo history covers both.
*   [Live excerpts](https://github.com/TriliumNext/Trilium/pull/11925) quote blocks of another note. They stay in sync, and an edit made in the excerpt is saved back to the source.
*   [Block references](https://github.com/TriliumNext/Trilium/pull/12069) link to a paragraph, heading, table or range of blocks. The target opens scrolled to the block and highlighted, and on a shared page every block has a public link of its own.

Layout caught up with content. [Multicolumn layouts](https://github.com/TriliumNext/Trilium/pull/11958) put two to four columns side by side and stack them on narrow screens. [Drawing canvases](https://github.com/TriliumNext/Trilium/pull/11829) are sketched in place with Excalidraw and saved with the note. Files are [attached](https://github.com/TriliumNext/Trilium/pull/11795) in one step, as inline embeds for PDFs and spreadsheets or as links, and YouTube videos and web audio or video play inside the note. A block handle moves blocks, images and tables, a "+" on an empty line opens the slash commands, and one [link dialog](https://github.com/TriliumNext/Trilium/pull/12358) serves web links, note links and anchors from a popover at the cursor.

The include box itself was [reworked](https://github.com/TriliumNext/Trilium/pull/11798): a compact title row with a caption, fullscreen, a link from the embed to its note and back, Markdown included as source, split or preview, code with folding and line numbers, and resizing by dragging a corner or an edge. [Content tabs](https://github.com/TriliumNext/Trilium/pull/12063) group blocks under a scrolling row of titles, above or below the content, with a menu to add, reorder or delete tabs and Ctrl shortcuts to move content between them.

Contributed by @adoriandoran.

### Tables in text notes

Tables were the editor's weak spot: no merged cells, no sorting, and anything past a few rows meant switching to a spreadsheet note. The [table context menu](https://github.com/TriliumNext/Trilium/pull/11774) now merges and unmerges cells, distributes columns, and inserts or deletes many rows and columns at once. A column sorts by its values, with dates, times, numbers and text detected and ordered per the note's language, and Alt+arrows move rows and columns while keeping merged cells and header rows intact.

Wide tables scroll sideways under a sticky header, and on touch screens a column bar resizes and selects columns while corner handles select cell ranges. The insert form takes any size up to 1000 × 100, with header rows and columns.

Contributed by @adoriandoran.

### AI that asks before it acts

Two things kept many users away from the AI integration: paying per token, and handing a model write access to their notes. Both change in this release.

ChatGPT Codex subscriptions, including the free plan, and OpenRouter join Claude Code, GitHub Copilot and Antigravity as providers, so an existing subscription can drive Trilium's chat. [Custom search engines](https://github.com/TriliumNext/Trilium/pull/11878) (Brave Search, Tavily, Exa, Serper, Perplexity, or a self-hosted SearXNG) give web search to local models and to providers that have none of their own, such as DeepSeek.

[Before a tool runs](https://github.com/TriliumNext/Trilium/pull/12116), the chat shows what the AI is about to read or change and waits for you to allow or deny it, for that call or for the rest of the conversation. The Tools menu sets the default: always ask, ask only before changes, or never ask. It works the same with API keys and with subscription providers.

### Shared pages look like the app

A note shared to the web rendered in a theme of its own, and a shared collection appeared as a plain list of its children. Shared pages now use a [theme built from the app's own look](https://github.com/TriliumNext/Trilium/pull/11979), in light and dark, and a shared board, table, calendar or other collection renders with the same view it has inside Trilium.

Drawings appear as theme-aware SVG pictures instead of a download link, and every block of a shared note has a public link, copied from its block handle, that opens the page scrolled to that block.

### Mobile without the sidebar

On a phone, the sidebar was both the note tree and the only way around the app, and it covered the note every time it opened. The iOS and Android apps get a [navigation system that does without it](https://github.com/TriliumNext/Trilium/pull/12279), and iOS gets a [layout redesigned](https://github.com/TriliumNext/Trilium/pull/12263) in the style of iOS 26.

While editing, the formatting toolbar floats over the note as a compact island, shown only while you type, and brings the widget, link and list toolbars along.

## 🔄 Compatibility

*   The sync protocol version went from 39 to 41: instances on different versions cannot sync with each other, so update the server and every desktop and mobile client together.
    *   [The sync protocol was extended so that the reworked include notes sync without risking data loss between clients, which is why this release raises its version.](https://github.com/TriliumNext/Trilium/pull/11798)
*   The database version went from 240 to 242: the database is migrated the first time this version opens it, after an automatic backup, and an earlier version refuses to open it afterwards.
*   The Docker image has been reworked so that it can run as a non-root user. Look for the corresponding section in the [Docker setup documentation](https://docs.triliumnotes.org/user-guide/setup/server/installation/docker). ([#5790](https://github.com/TriliumNext/Trilium/issues/5790))

## 🚨 Breaking changes

*   The old layout has been removed. It's been almost a year since the new layout was introduced and we believe it has been polished enough to see day-to-day use. For more information, see the [corresponding GitHub Discussions post](https://github.com/orgs/TriliumNext/discussions/11891).
*   Multi-level `#sorted` values introduced in v0.106.0 must now write labels with `#`, as search's `orderBy` does: `#sorted="priority desc, dueDate"` becomes `#sorted="#priority desc, #dueDate"`. Values without `#` fall back to sorting by title. A single name (`#sorted=myOrder`) and property-only values (`dateModified desc, title`) are unaffected. See [Sorting Notes](https://docs.triliumnotes.org/user-guide/concepts/notes/sorting).
*   `POST /etapi/auth/login` now requires a code if TOTP is enabled. Check the API documentation for more information.

## ✨ Improvements

1.  Interface: Context menus and note autocomplete were rewritten from scratch. Menus gain [keyboard navigation](https://github.com/TriliumNext/Trilium/issues/1166) and better accessibility, no longer [clip](https://github.com/TriliumNext/Trilium/issues/5294), and the note tree menu is more compact. [Autocomplete](https://github.com/TriliumNext/Trilium/issues/5134) has a modern design, the command palette, link and relation pickers, `@`-mentions in text and Markdown notes and attribute value suggestions. ([#5493](https://github.com/TriliumNext/Trilium/issues/5493), [#11896](https://github.com/TriliumNext/Trilium/pull/11896), [#11833](https://github.com/TriliumNext/Trilium/pull/11833))
2.  Text editor: [Theme-adaptive colors: text, highlight and table colors stay legible when switching light and dark themes](https://github.com/TriliumNext/Trilium/pull/11788) by @adoriandoran
3.  Text editor: [Smarter paste: text copied from Chrome and Chromium-based applications (e.g. VS Code) is stripped of colors, backgrounds and table styling.](https://github.com/TriliumNext/Trilium/pull/11854)
4.  Desktop: Meetings can be transcribed locally (experimental), with an on-device speech model downloaded on demand, live audio levels, a transcript card that can be copied and a consent reminder. ([#12079](https://github.com/TriliumNext/Trilium/pull/12079), [#12083](https://github.com/TriliumNext/Trilium/pull/12083), [#12101](https://github.com/TriliumNext/Trilium/pull/12101))
5.  Collections: [Geo map properties dialog, with image maps set up graphically: pick an image note as the map (a fantasy world, a floor plan, a campus), choose between the image's own pixels and custom corner coordinates, toggle a dark style, and set the map style, scale, labels, clustering and nesting depth, all of which were hand-written `#map:*` attributes before.](https://github.com/TriliumNext/Trilium/issues/11928)
6.  Calendar: The calendar collection catches up with the board: a properties dialog, attributes on events, and recurring events that [know their age](https://github.com/TriliumNext/Trilium/pull/11601).
    *   The Calendar properties dialog lists the calendar's settings (hidden weekends, week numbers, time slots, archived notes) and its event templates in one place, and an Event attributes card chooses which attributes the events show and in what order. Attributes nobody has arranged stay off the events, so existing calendars keep their current chips.
    *   The event context menu sets an event's attributes in place, as a board card's does, so a flag, state or date changes without opening the note.
    *   A yearly event can show how many years it has recurred: with Yearly selected, the Repeats dropdown offers "Show the number of years in the title", which writes `#calendar:titleTemplate="${title} (${years})"` on the event. A birthday entered once in 1990 reads "Ana's birthday (36)" in 2026 and counts up every year.
    *   Routine events (a daily stand-up, lunch) can be hidden from the month, year and list views through the properties dialog.
